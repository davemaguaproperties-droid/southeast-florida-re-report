# Self-hosted GPU runner setup

The workflow template expects a GitHub Actions runner with labels:

```text
self-hosted, linux, x64, cuda, gpu
```

The runner host must be a machine you control with an NVIDIA GPU and a working driver. GitHub runner registration is repository-specific and requires a short-lived registration token; never commit that token or place it in the workflow.

## Host checklist

1. Install a current NVIDIA driver and verify it:

   ```bash
   nvidia-smi
   ```

2. Install Python 3.12 and basic build tools.
3. Create a dedicated, non-root OS user for the runner.
4. Keep the runner on a private network where only required outbound GitHub HTTPS traffic is allowed.
5. Do not run untrusted pull requests on a persistent self-hosted runner. Prefer `pull_request_target` only with extreme care, or restrict CUDA jobs to trusted branches and manual/nightly dispatches.

## Register the runner

In the GitHub repository, open **Settings → Actions → Runners → New self-hosted runner**, select Linux x64, and follow GitHub's generated commands. The generated commands include the correct repository URL and one-time token.

When prompted for labels, add:

```text
cuda,gpu
```

A typical generated configuration ends with the equivalent of:

```bash
./config.sh --url https://github.com/OWNER/REPOSITORY --token REGISTRATION_TOKEN --labels self-hosted,linux,x64,cuda,gpu
./run.sh
```

Use the exact commands generated by GitHub for your repository; do not reuse a token.

## Run as a service

After verifying an interactive run, install the runner as a service using the generated runner package's service instructions. Confirm the runner is shown as **Idle** and has all expected labels before enabling scheduled benchmarks.

## CUDA/PyTorch compatibility

The workflow installs a CUDA-enabled PyTorch wheel. The host needs a sufficiently new NVIDIA driver, but does not necessarily need the matching CUDA toolkit installed system-wide because the wheel supplies most user-space CUDA libraries. Match the wheel index in the workflow (`cu124` in the template) to the driver support on the host and validate with the workflow's `torch.cuda.is_available()` step.

## Placement

Copy `github_actions_cuda.yml` into the consuming repository as:

```text
.github/workflows/ssi-ai-cuda.yml
```

Copy the three SSi-AI scripts into the repository's skill path, or adjust the workflow paths if the skill is stored elsewhere.
